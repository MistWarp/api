# Breach response procedure

Version 2026-10-01. A personal data breach is any security incident that leads to student or teacher data being lost, destroyed, changed, disclosed or accessed without permission. That includes accidents, such as a bug that shows one class's data to another teacher.

## Timeline

| When | What |
| --- | --- |
| Straight away | Contain it: revoke sessions, disable the affected route or feature, rotate secrets, take the API offline if needed. |
| Within 24 hours | Work out what happened, which data, which classes and schools, and how many students. Start the incident log below. |
| Within 48 hours of becoming aware | Tell every affected school, as the Data Processing Agreement promises: notify each teacher of the affected classes inside MistWarp, and email any contact the school has given. Include what happened, the data and number of students involved, the likely consequences, and what MistWarp has done and will do. |
| Within 72 hours | For breaches of teacher or billing data, where MistWarp is the controller, report to the ICO unless the breach is unlikely to result in a risk to people. For student data, help the schools with their own ICO reports. |
| As needed | Tell affected people only with the school's agreement, unless the law requires otherwise. For US schools, follow the notice timelines in any state data privacy agreement the school has signed. |
| Afterwards | Fix the cause, add a test that would catch it, and update the DPIA and security programme. |
